# OSS README Blueprint

## Purpose
Use this pattern when converting an internal app repository into an open-source-ready project README.

## Recommended structure
1. Hero with one-line tagline and short value proposition
2. Screenshot placeholder or asset reference near the top
3. Key features bullets
4. Architecture section with a lightweight diagram
5. Prerequisites list with install links
6. Manual deployment steps with copy-pasteable commands
7. Automated deployment / CI setup with required variables in a table
8. Local development instructions per app surface
9. Testing commands
10. Contributing guidance and workflow conventions
11. License section
12. Optional acknowledgments

## Rules of thumb
- Prefer deployment-first ordering over deep implementation detail.
- Keep commands runnable for a first-time contributor.
- Replace personal domains, emails, and IDs with neutral placeholders.
- Use tables for environment variables and GitHub repo variables.
- If a screenshot is not ready yet, keep the README reference and add an explicit maintainer note.
